系統定位

本地零信任安全防禦矩陣 (acore)

acore 是一套本機運行的 2FA 金鑰防禦矩陣，專為代管大量高價值帳戶之企業與管理員設計。

🛡️ 核心安全防禦邊界

系統架構基於 Chrome Extension Manifest V3 最嚴格的安全防範模型建置，並遵守以下三大核心原則：

01

絕不儲存明文密鑰

任何寫入瀏覽器本地資料庫（chrome.storage.local）的資料皆經過加密保護。即便電腦硬碟被實體拷貝，無主密碼亦無法解密。

02

絕不依賴外部網路

所有加密、解密與 TOTP 計算完全在瀏覽器本機的隔離沙盒內運行。外掛不請求任何網路存取權限，徹底杜絕資料外流的通道。

03

記憶體即用即收

2FA 密鑰解密後的明文變數在記憶體中留存時間不超過 1 秒，每次計算完成後立即使用 fill(0) 覆寫記憶體空間，防止記憶體傾印攻擊。

🏗️ 隔離與 IPC 安全模型

為了防止惡意軟體藉由偵測擴充功能內部訊息傳遞（IPC）來竊取密鑰，acore 實施了多重隔離設計：

網頁前端 UI 隔離層 (Popup - 不持有密鑰)
1-to-1 動態 ECDH 金鑰加密 IPC
密碼學核心沙盒 (Background SW - 僅在記憶體解密)
AES-GCM (256-bit)
本地加密儲存區 (chrome.storage.local - 密文狀態)
部署說明

瀏覽器外掛安裝與配置

acore 是完全本地化的 Chrome 擴充功能，不依賴任何外部商店或伺服器下載。

🛠️ 逐步安裝指引

第一步：下載專案原始碼

將 acore 外掛專案包解壓縮到您本地電腦的指定目錄（例如 C:\acore）。

第二步：開啟開發人員模式

在 Chrome 瀏覽器網址列輸入 chrome://extensions/，進入擴充功能管理頁面，並勾選右上角的「開發人員模式」。

第三步：載入未封裝項目

點擊頁面左上角的「載入未封裝項目」按鈕，選擇剛剛存放原始碼的專案資料夾即可完成安裝。

密碼學安全機制

系統核心防禦鏈由 Web Crypto API 的強大演算法建構而成，絕不依賴第三方外部庫。

🔑 雙層金鑰衍生與加密儲存

當使用者首次開啟外掛並註冊帳戶時，系統透過以下密碼學流程進行密鑰保護：

A

PBKDF2 金鑰衍生 (KEK)

利用使用者輸入的主密碼，結合 16 位元隨機鹽值（Salt），經過 100,000 次 SHA-256 反覆迭代計算，衍生出 256 位元的對稱加密金鑰（Key-Encrypting Key, KEK）。

B

AES-GCM (256-bit) 對稱加密

系統每次寫入金鑰（如 TOTP Secret）或儲存設定時，皆隨機產生唯一的 12 位元初始化向量（IV）。加密後的產物包含密文（Ciphertext）與驗證標籤（Tag），提供機密性與完整性校驗。

🔒 ECDH 訊息加密 IPC 通道

為了防範同瀏覽器下的惡意擴充套件通過監聽 `chrome.runtime.onMessage` 來攔截密碼，Popup UI 與 Background Service Worker 之間每次通訊皆進行 ECDH 金鑰交換：

  • Popup 載入時，在記憶體建立臨時的 ECDH (P-256) 金鑰對，並將公鑰傳送給背景 Service Worker。
  • 背景 Service Worker 收到後，亦生成自己的 ECDH 金鑰對，並依此計算出共享金鑰，將其公鑰回傳給 Popup。
  • 雙方基於該共享金鑰衍生出一組 256 位元的 AES-GCM 金鑰，此金鑰僅存於各自執行緒的內存變數中。
  • 此後所有 IPC 通訊資料（包括解鎖密碼、新增金鑰、產出 TOTP 碼）皆使用此動態金鑰加密傳輸。

備份檔案格式與還原標準

零知識備份機制（Zero-Knowledge Backup）確保使用者金鑰可攜性的同時，亦不洩漏任何機密資訊。

📋 JSON 備份資料格式規格

當使用者選擇導出備份時，背景程式會將整個加密儲存庫包裝成 JSON 導出。以下為其完整的資料規格格式：

acore_backup_schema.json 
{
  "salt": "uWz6H0bN2rD58iPqQvL9+A==",  // 用於衍生 KEK 的 16 字節 CSPRNG 隨機鹽值 (Base64)
  "sentinel": {
    "iv": "kPn9XmYt5Rq1aBc7",         // Sentinel 加密使用之 12 字節 IV (Base64)
    "ciphertext": "z8JqP+4dFh2..."    // 解密後應為 "ZeroTrustSentinel" (AES-GCM 密文)
  },
  "vault": {
    "iv": "wQe9RnT5Yu3iOp8A",         // 密鑰資料庫加密之 12 字節 IV (Base64)
    "ciphertext": "a1b2C3d4E5f6..."   // 解密後為包含帳戶金鑰的 JSON 陣列密文
  },
  "logs": {
    "iv": "zXy8Wv2Ts5Rq9PmN",         // 安全審計日誌加密之 12 字節 IV (Base64)
    "ciphertext": "m9n8B7v6C5x..."    // 解密後為歷史審計日誌之 JSON 陣列密文
  }
}

🔄 還原解密解析流程

在還原時，系統會先依據備份檔內的 salt 與使用者輸入的密碼衍生出臨時 KEK，試圖解密 sentinel。若解密文字為 ZeroTrustSentinel，則驗證密碼成功，進而解密 vault，並以當前系統的 active KEK 重新加密寫入 chrome.storage.local，完成還原。

合規審計

企業安全審計日誌規範

acore 在本地維護一份不可篡改且全程加密的安全日誌（Audit Logs），用以滿足企業客戶的安全合規與存取追蹤需求。

📝 日誌物件架構規格

每次使用者進行關鍵操作（如解鎖、新增金鑰、複製驗證碼、自動填入或匯出備份）時，系統皆會將該操作時間戳與詳細內容加密寫入日誌庫中。

audit_log_schema.json 
[
  {
    "timestamp": 1780560000000,              // 事件發生的毫秒級時間戳
    "event": "Vault initialized"            // 事件行為描述
  },
  {
    "timestamp": 1780560120000,
    "event": "Added account: Discord (admin)"
  },
  {
    "timestamp": 1780560250000,
    "event": "Copied TOTP for: Discord:admin"
  },
  {
    "timestamp": 1780560300000,
    "event": "Autofilled TOTP for: Discord (admin)"
  }
]

🛡️ 日誌竄改防範

審計日誌儲存在加密的 logs 欄位中，除非使用者提供正確的主密碼解密金鑰，否則本機檔案將一直保持加密狀態。這使得任何未經授權的本地修改與寫入在解密時都會被驗證標籤（Tag Mismatch）拒絕，進而保證日誌的真實性與合規完整度。
